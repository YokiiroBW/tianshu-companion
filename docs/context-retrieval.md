# 更正上下文检索

TS-307：当前准备使用 `memory-context/v2` 的统一 query，规范事实与长期来源 episode 共用预算；近期人类原话和既有关系/画像上下文继续装配。`memory_state` 保留对象、原子属性、modality 和有效时间，`episodes` 保留作者与原话，`memory_coverage` 明确匹配及未解决部分。planned 不能由时间经过变成 observed，也不能据缺少执行证据断言没有执行；旧自由描述以 legacy 证据保留，不猜补原子状态。

可选近期回复的证明闭包只能引用本次已选上下文组和必需依赖。若旧回复依赖窗口外材料，复用已有完整 `input_only` 投影，保留仍有效的人类原话并标记 `reply_text_visibility=omitted`；不把整段历史递归带入新回复。显式方案/续写依赖仍全部检查。Memory bundle 与继承的 select/history/input-history/profile 检查在每个边界合批，超过64项拆分为多个有界请求，全部成功才可继续。Core 原作者、来源、渠道、绑定、租约与发送前检查保留；不复用跨边界授权缓存。保留的 v1 轮次沿旧读取与可选上下文预算恢复。

显式记忆工具提交成功后，v2 路径重新运行同一上下文装配，更新规范事实和原话，同时恢复被保留材料的完整检查；不会只换事实正文却留下未验证的旧回复或画像。实际模型是否正确使用这些材料仍由独立语义评测验证。

普通回忆问题仍先使用 Memory 的授权召回，再由 `select_recent` 补充同一会话内的近期原话。TS-171 修复了旧话题词命中最初安排，却漏掉“改成东门”这类省略地点名后续消息的问题。

返回旧话题时，保留命中输入和随后最多两条邻近人类输入；显式改口线索可继续延伸邻近片段。中间的其他人物和活动不被删除或改写，模型必须根据各条原话及身份判断更正对象。检索不合并人物、不认定群成员已同意、不把提议标成已发生的事实。对于多个候选活动，无法明确归属时保留不确定性。

如果命中的输入本身就是改口，则同时向前带回至多两条邻近原话，防止只看见新名称或新地点，却失去原始对象、旧名称和未改动对象的描述。前后片段仍作为完整组经过同一预算及授权检查，不能拆掉其中的更正。

普通事实回忆优先选择有词项关联的人类陈述，再比较相关程度，避免重复追问因词面更接近而挤掉最初给出内容的原话。明确询问助手以前如何回复时仍允许原问题作为检索入口；无关陈述不会仅因不是问句而获得优先。

即使原话仍在轮次数窗口内，普通相邻消息加助手回复超过字节预算时，也使用上述有界检索保留相关人类原话。不会先用冗长助手回复耗尽预算，再将实际被问到的人类输入直接丢掉。仍不截断单条输入或一组更正，也不扩大字节限制。

原安排和这些后续消息作为一组进入预算与授权检查。组太长、超出字节预算或有成员不可用时整组省略；不能只留下旧安排。重叠候选也不能被裁成缺少后续消息的片段。已接受消息仍按原会话顺序呈现。旧话题的人类原话及补充的邻近输入通常不附带助手回复，避免助手扩写占用空间、被当作人类确认或带回另一个话题的依赖链；明确询问助手此前建议、方案或回复时仍保留已确认发送的回复及其依赖。普通连续对话仍保留已发送的相邻回复。

没有扩大读取范围：沿用既有同角色、群/私聊、房间/线程、绑定、人物、来源和版本检查，最多扫描现有 128 条候选，最终仍受部署配置限制。当前默认是 4 组、8192 UTF-8 字节、1800 秒；未发送、未知发送及被撤回内容不会因词匹配重新出现。模型前和发送前仍新查授权及来源，来源投影不继承未展示助手回复的其他依赖。

这是有界对话上下文检索，不是新增持久事件账本。它不会把短暂安排自动推广为稳定偏好，也不会为此前被抽取器跳过的活动补写长期事实。超出历史时限或预算、目标不清、原话撤回等情况仍可能查不到。自动抽取是否真正提交，继续以 Memory 的现有回执为准。

原话投影使用 Memory 的 `/internal/v1/memory/context/input-history` 快照：自动地点更正会使依赖旧结论的助手回答失效，但不会撤销尚有效的人类原话。含助手回答的上下文仍使用原 `history` 快照和完整依赖。两条路径都保留原作者授权、绑定、关联和来源复核；明确遗忘、撤权、撤回仍使原话失效。既存轮次没有新快照时按原严格历史检查处理，不追认旧内容。端口沿用已发布 context-history 结构和 context_query 权限，后续应先发布 Memory 再发布 Companion。

相关验证：`tests/test_correction_context.py`、`tests/test_input_history_client.py`、`tests/test_context_retrieval.py`、`tests/test_short_context.py`、`tests/test_continuation_revision.py`、`tests/test_context_scheduling.py`。模型语义及原生链路计时单独记录，不能用本地字符串断言代替模型实测。

TS-190 继续区分召回与解释：原话中每次改动的理由只解释那一次改动，不能拿前次理由推断后来的改回；没有说过原因时明确保留未知。回忆问句只回答被询问的内容及必要限定，不顺带列出其他记忆或把刚召回的内容再次当作写入承诺。这是现有回答指令的收敛，不额外调用模型，不改写原始消息，不保证模型绝不误解；采用独立的新场景验证原因归属、未知原因、不同人物与话题克制。核验并发与取消的确定性回归见 `tests/test_context_checkpoint.py`。

相邻上下文尚无任何已发送助手回复时，也按人类原话核验，不继承未展示回复所依赖的画像或更早回答。否则画像变化会使仍然有效的原话一并消失。片段包含已发送回复时，先核验完整回复依赖；如果回复失效，再独立核验整组人类原话，仅在原话仍有效时保留输入并删除全部回复、标记input_only。原话撤权、遗忘或来源失效仍省略整组，不能留下缺少更正的旧安排。原作者、渠道、绑定及原话历史核验始终保留，模型前或发送前不会对已用失效材料做这种替换。`test_profile_context.py`和`test_context_checkpoint.py`验证回复失效、原话仍有效以及原话也被撤回的不同情况。

TS-192：更正线索按分句区分新陈述、试探提议和回顾追问。“为什么改到……”“改到哪儿来着”等追问不再把整个更正片段向后延长；“要不换到……”“改到……吧”仍随原话进入上下文，不因此视为已经达成共识。包含先陈述更改、再询问对方的消息仍保留陈述。补充“日期又改了，最后定……”等省略式线索，避免忽略真实后续更改。原整组预算、完整更正与撤回保护保持，不能为了命中旧原因而切掉后来的更正。这仍是有界词项选择，不宣称理解任意自然语言关系。

回答继续引用原话中的人物与事件：单人提议不能说成全群同意，提问中的“大家说好”也不是确认；事件发生时间不能替代发言时间。没有被问到且没有依据的消息顺序、发言时刻或活动完成状态不附加到简短回忆答案中。有效性以隔离模型评测为准，不用提示词存在本身代替验收。

TS-192复测补充：仅有权限和版本有效，并不保证助手旧回复中的推测正确。相关的事实问句也使用人类原话投影，不再只在超长/旧话题检索时移除助手回复；“叫什么”等简短事实问句不依赖中文双字词恰好重叠。明确问助手此前如何回答、建议或称呼时仍保留已发送回复；普通叙述继续使用原邻接规则。对近期独立的人类陈述，即使冗长助手回复会超出预算，也按完整近期原话选取，避免一个较新的确认片段覆盖掉另一位的确认；更正锚点仍保留原有前后完整批次。原始历史未删除，来源、身份、遗忘和权限检查未省略。

来源投影给出已选人类消息的局部发言者引用、人物引用和原有顺序。TS-218 在最终模型投影时，仅在明确询问消息发送/接收时间、日期或当前钟点等问题时，将发送与收到时间置于独立的 `transport_clock` 来源元数据中；普通事实回忆不再重复附上原始钟点或相隔秒数。它不解释正文中的“昨天”等事件时间，不复制正文进系统指令，不扩大来源范围或授予权限。同一人物的闲聊和后来确认属于同一个发言者；当前群聊中其他成员公开说过的事，可以说明来源后回答，不因提问者自己的长期记忆为空而拒绝。这些元数据帮助模型区分事件和发言时刻，仍须以实际回复检验其是否遵守。

近期命中的更正本身仍可能省略对象，所以事实追问命中更正时，无论助手回复长短、是否触发字节压缩，都按完整更正片段回带原始陈述。仅保留“周二要看牙，所以换周三”会丢掉原句中的培训对象；不能因为这句话恰好还在最近四组内，就直接截取最近四组。回归同时覆盖短回复和长回复，要求原安排、首次原因和最终日期都在窗口内；仍不拆开被撤回或超预算的更正组。

同人多次发言另有按发言者汇集的文字视图：每人一组，组内先历史原话、后当前输入，并保留消息引用，避免将某人先前未表态与后来的确认计成两个成员。TS-218 为原话时间词增加最多八个精确文字跨度，统一标为发言者自述，不推算时区、事件日期或事实生效范围；原始发送/收到钟点不再复制进此文字视图。文字视图只进入用户数据消息，系统段只含身份/来源元数据；原始消息、验证上下文和依赖不被修改。视图只覆盖本次选中的作者，不是完整群成员名册，不能据此给其他人补写态度。此视图不判定同意、不存共识账本，最终表达仍需模型实测。

TS-202：人物/时间/表态的回答约束归属 `qq_identity.SOURCE_INSTRUCTION`，避免继续在 Core 装配段堆规则。删除容易被当作实际人物特征的例子，称呼只来自该人的原话。提议者已有意向，不能因为没再说“同意”而被称为未表态；仅提议或部分确认不能先肯定“大家已经说好”。个人退出不代表全体取消，缺少选中消息也不证明某人没有表态。文字视图同时带原发送与收到时间，但均不视作事件日期；相对时间只限定对应事件，没有明确当地日期/时区时保留原词，不推算额外日期。

TS-218 的上述最终模型投影覆盖 TS-202 重复提供原始钟点的方式：`context_time` 只改变提示渲染，持久消息、来源授权、历史快照和核验仍读取原始时间。实际提示字节数按渲染后内容记录，材料接纳仍使用原始来源的保守预算。明确询问助手以前如何称呼或回答时继续保留已发送助手回复。时间措辞仍由生成模型决定；隔离实测中事件与命名日期已能分开，但有一次归属回答仍多补了自述钟点，不能称时间问题全部解决。

新建 Core 的消息合并默认静默窗口为 1500ms，仍按同一发言者滑动合并，保留去重、连续消息和显式 `max_wait_ms` 语义。部署若已经显式配置 5000ms，该值继续生效；发布时需单独将既有 `policy.silence_ms` 更新为 1500，其余配置保持。日常模型不变，不能把此程序等待的减少等同于模型推理提速。

泛指“谁同意了”的查询可能没有地点或日期。检索现在从最相关的人类表态中借用话题词，再查找它对应的原始提议；这些词只是检索线索，不是共识或权限证明。原有范围、组数、字节预算、来源核验和完整更正片段规则保持。

暂时的模型依赖失败不应抹去已经受理的用户原话。只有曾进入模型阶段、失败码为 dependency_unavailable、且持有独立 input_history_snapshot 的轮次，才可将人类输入作为 input_only 候选重新核验；不恢复其任何机器人回复。缺独立快照、授权失败、取消、撤回、绑定变化和过期的内容仍排除。每次使用继续经过现有精确人物/渠道/来源检查，不能据此读取其他群或私聊，也不把失败回复当作已经送达。
