# ADAPTER-H 交接：两宿主自助 RPC 插件候选

- 目标：用户在网页选 AstrBot / NoneBot，填受控插件地址与一次本机获取的密钥；平台按固定 `tianshu.bot-adapter/v1` 协议拉事件、推回复，机器人宿主不需填写天枢内部 ID、回调、Core 地址或服务 token。
- 基线：Companion `ad180ca`；实现提交 `5ece93a28da069d9fb0f7bea0e3441e4d55a5f92`。只改 `integrations/`、插件定向 `tests/` 和本交接，不改 Core `src/`、`pyproject.toml`、锁或其他测试入口。

## 实现

- 共用 RPC v1 服务按字节相同地 vendor 到 AstrBot ZIP 与 NoneBot wheel：7 个固定 POST 路径、Bearer 鉴权、64 KiB 请求 / 256 KiB 响应、8 并发、20 秒 HTTP 上限；SQLite WAL/FULL 持久实例 ID、自动密钥、版本化绑定、精确作者与会话白名单、入站队列和 SDK 发送意图/回执。未 ACK 事件可重读，同 attempt 只调用一次 SDK，进程中断的 `inflight` 变为 `unknown`。上限为 1 万未 ACK 事件、2 万历史记录；满后拒绝新工作，不删未知发送意图。输入 8000 字符，输出 32768 UTF-8 字节，不拆分。
- AstrBot 4.27.3：真实 aiocqhttp SDK 的反向 WebSocket API 连接及 `get_login_info` 确认在线 self_id；重复 self_id 的多个实例不暴露账号。插件 RPC 仅监听 `127.0.0.1`，默认端口 18765，可在 AstrBot 插件配置 UI 调整。旧 `enabled=true` 继续用原 pull 模式且关闭 RPC；默认适配器模式没有启用绑定就不接管聊天。密钥可用本机 `rpc.py show-key` 显示。
- NoneBot 2.5.0 + OneBot 2.4.0：使用现有 FastAPI driver 同一 ASGI 端口，真实 `on_message` rule 仅在持久入队后阻断；账号来自在线 Bot 的 `get_login_info`。`driver.on_shutdown` 移除 7 个路由并关闭 SQLite；旧 pull 入口与新入口互斥。独立 wheel 修复包初始化时旧 `bridge` 过早导入 Companion Core 的问题；密钥可用本机 `python -m tianshu_nonebot.rpc show-key ...` 显示。
- 构建脚本 `integrations/build_adapter_releases.py` 生成自包含候选，构建时验证三份 RPC 模块字节一致。安装说明分别见 `integrations/astrbot/ADAPTER.md` 与 `integrations/nonebot/ADAPTER.md`。

## 固定版本依据

- AstrBot v4.27.3 `Context.register_web_api` 只将插件 handler 放进 Dashboard `registered_web_apis`；Dashboard 固定路由 `/api/plug/{plugin_path:path}` 通过 `require_dashboard_user` 认证，不能由平台的插件 Bearer 密钥直连。源码：`https://github.com/AstrBotDevs/AstrBot/blob/v4.27.3/astrbot/core/star/context.py`、`https://github.com/AstrBotDevs/AstrBot/blob/v4.27.3/astrbot/dashboard/api/plugins.py`。因此 AstrBot 采用回环监听，远程平台需要宿主侧现有私网 HTTPS 反向代理原样转发固定前缀；本候选不打开公网端口。
- NoneBot v2.5.0 FastAPI driver 暴露 `asgi`/`server_app`，插件可在该应用注册固定路径，启动和关停经 driver lifespan；源码：`https://github.com/nonebot/nonebot2/blob/v2.5.0/nonebot/drivers/fastapi.py`。OneBot v11 2.4.0 SDK 在隔离环境实装，类型事件与原生发送路径用于合成回环验收。
