目标：对已发布查询恢复一次可识别的连接传输失败，维持相同请求、凭据、TLS 和总预算，不重放写操作或干扰另一准备轮次。

## 变更与审查

- JsonService 显式列出五个 POST 查询：origin resolve、identity resolve、Memory select、profiles select、source-sync check；另精确匹配当前 Gateway 生成的 GET model-request 回执路径。所有 src 与 NoneBot integration 调用者均已审查。
- 请求仅构造一次；响应头前 RemoteProtocolError/ReadError/WriteError 至多恢复一次，查询两次发送及读体共 15 秒。取消原样传播。HTTP拒绝/冲突、JSON/schema、读体失败、connect/证书/超时错误不重试。
- 输入授权可能持久冻结路由或签发上下文，排除 source-access/read；其他未列路径和所有写命令默认单发。Memory 来源屏障可提交失效/水位，已明确查询恢复不等于无服务端执行，恢复后继续现有范围与版本检查。
- 不关闭/替换共享 client，不改 keepalive、CA 验证、wire、依赖锁或消费者 unknown 语义。增加 `tests/test_query_transport.py` 和 `docs/query-transport.md`，AGENTS 登记实际验证命令。
- 稳定改动完整 diff 与新增文件已审查，只有上述任务范围文件；没有修改其他产品、发布合同、根任务板或 TS-050 历史证据。
