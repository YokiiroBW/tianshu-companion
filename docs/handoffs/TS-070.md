## 实际变更

### 1. `src/tianshu_companion/life.py`（有证据的最小修复）

- 日记行与 revision 增加 `fictional=True`：生活日记始终是虚构条目，此前只有素材逐条带
  `fictional`，日记本体与正式内容没有该标记（对比 `image_jobs` 一直带 `fictional=True`）。
- `diary_metadata` 增加捕获标记：`fictional`、`config_version`、`material_version`、
  `recipe_id`、`recipe_version`；旧行没有 `fictional` 字段时按虚构生活行处理（`item.get(..., True)`），
  不改写历史数据、不做结构迁移。
- `read_diary` 的正式内容返回 `fictional` 与 `material_version`，读者可判定该内容对应哪次素材快照，
  不会把旧草稿/旧捕获当成当前状态。授权检查仍在读取正文与素材之前，未新增
  `life_revisions`/`life_materials` 读取（原有 guard 用例继续通过）。

证据来源：`tests/test_life_chain.py` 首次运行时 `assert meta["fictional"] is True` 直接
`KeyError: 'fictional'`，即日记捕获标记缺失。图像侧已满足“标记捕获版本”（任务已带
`snapshot` 的 actor/room/world 版本、`outfit.version`、`workflow_version`），因此未改动。

### 2. `tests/test_life_chain.py`（新增，4 个用例）

一个共享世界、一个房间、两个角色、固定民用时间（+08:00 12:00），全部为虚构标识、合成事件、
本地 stub ComfyUI 与模型替身：

- `test_chain_knowledge_state_diary_capture`：participated/witnessed 获知分离；未获知角色不能
  `tell` 转述；手动保持经受结算、只由显式 `resume_*` 或到期解除；日记素材/草稿带捕获标记；
  模型请求载荷中 B 不含 A 的私密事件（B 未获知不进入 B 日记）；发布按素材版本一次；
  之后的新事件产生新任务而不覆写已发布版本；重启后事件数不变、同素材任务不重复入队、
  正式版不重复发布、`source_head` 不变。
- `test_chain_shared_room_conflict_and_manual_hold`：同房间控件按 actor id 升序由后者建议优先，
  手动保持不被日程或另一角色覆盖，`resume_room` 后才回到自动。
- `test_chain_image_capture_survives_state_change_and_restart`：图像任务冻结
  actor/room/world/outfit/工作流版本与渲染图；之后活动、房间、衣橱版本变化都不改写已存任务；
  与本地 stub 完成一次真实 HTTP 往返（提交、history、/view 下载、PNG 校验、`archived=false`）；
  图像完成不改写生活状态；重启后已提交任务不重发、终态不变、捕获不变。
- `test_chain_chat_summary_and_image_capture_share_one_state`：聊天上下文 `fictional_life` 摘要
  与图像任务读数来自同一生活状态；摘要是当前版本，而更早捕获的任务保留自己的版本。
