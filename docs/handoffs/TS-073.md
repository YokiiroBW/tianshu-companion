  排队/生成中的尝试作废为 `invalidated` 并标记请求；
  **已发布正文、修订行与发布历史不被改写**。清除标记需显式 retry（重钉正典）或人工 revise。

## 局限与下一步

1. 模型是否真的遵守大纲/人物/前文一致性不由本模块保证；字符串长度与状态检查不证明叙事质量，
   必须人工审读。`candidates` 只提供可追踪的候选新设定，`apply_candidates` 才写入人物正典。
2. 作品只持久化在 Core 内部；没有网页/HTTP 路由、没有跨产品合同、没有正文导出或渠道发布。
   `docs/writing.md` 末尾的跨产品候选未发布、未实现，需双方 schema/样例/验收后再冻结。
3. 依赖漂移以固定素材哈希为准并优先给出命名原因；无法归因到版本化字段的素材变化统一记为
   `material_changed`（例如前章标题，或前章由未发布变为已发布而改变其 `standing`）。
   工作标题与展示性文案不进入素材，改名不会被当成依赖变化。
4. 崩溃可能让一次已提交的生成永久停留在 `unknown`（无结果可取回），需人工决定重试或取消；
   本模块不会自动重发，也不声称能取回已丢失的模型结果。
5. 迁移恢复须停机、隔离 DB/WAL/SHM 再复制完整备份；本次只用临时合成数据库，未操作生产数据。
6. `_save(expected=None)` 的内部写入路径沿用 life 既有模式（只在显式传入 expected 时校验版本），
   仅由 `work()` 的单飞锁与事务内重读保护；公共端口的每个变更入口都要求 expected。
   若将来把该端口暴露给多事件循环或多个宿主进程，应改为强制 expected。

## 独立只读复核（本轮内）

实现稳定后另起一次独立只读复核（未修改任何文件）。复核结论：没有高危缺陷；
“unknown 不自动重发”和“已发布正文不被隐式改写”在最强的对抗尝试下成立，
状态机无死路、`Store.put` 列映射无数据完整性错误。复核发现并已在本提交内修复：

- 中危：素材包含前序章节标题与前章发布状态，但 `basis` 只固定了修订号/摘要版本，
  因此仅改标题不会触发待复核。已改为比较 `material_version` 与按当前正典重算的素材哈希，
  并让 `_messages` 只发送被固定的内容；新增命名原因 `material_changed` 与回归测试
  （前章改标题、前章发布）。
- 低危：内容为空的章节在重新 pin 后仍保留旧 `review_required`。已在重新入队时对无稿章节清空该标记
  并加断言。
