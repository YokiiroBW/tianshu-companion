## 完成内容

- 新增 `core.proactive` 可信同产品端口（`src/tianshu_companion/proactive.py`）：
  显式订阅、角色持续目标、一次性提醒、候选与持久调度、派发 attempt 与额度账本。
  没有新增 HTTP 路由、没有新建跨产品合同、没有读取 Memory 与真实 source-facts。
- **默认关闭**：没有 `register_subscription` 就没有候选能进入 `ready`；订阅必须给出
  `consent`（`registered_by`/`basis`/`evidence_ref`），`basis` 只接受
  `explicit_user_request` 或 `explicit_admin_registration`。普通聊天文本、模型输出、
  画像字段都不是同意；提醒 `basis` 只接受 `explicit_registration`。没有任何健康数据入口，
  也不推断现实经历。
- **文案只用显式模板**：`put_template` 按 (id, version) 不可变，占位符仅限
  `summary`/`due_time`/`due_date`/`timezone`；模板缺失 `KeyError`，未知占位符 `ValueError`，
  登记时即校验渲染长度，避免调度期反复失败。**不调用模型、不使用 `config_version`、
  不占用模型槽位、不默默继承聊天线路**。
- **决策清单**：订阅状态/配置版本、目标状态/版本、`due_at + expiry_seconds` 到期、
  时区静默窗口（含跨午夜与同一天窗口）、冷却、未回复抑制、每日额度，依次给出
  `cancelled` / `expired` / `deferred` / `suppressed` / `ready`。
  未回复计数只依据 Core 已接受的 `collections`（真实 inbound），主动联系只写 `proactive_*`。
- **时间语义**：到期时刻一律绝对 UTC epoch，静默窗口是配置时区 civil minute；
  每次 tick 从持久行重算，时钟前进/回退与重启都不依赖已存本地时间。
  夏令时缺口取缺口后第一个真实时刻，回拨重复固定取较早一次（fold=0）。
- **派发纪律**：提交前在同一所有者事务内重读并复核来源、授权（宿主 `guard`）、
  候选版本、闸门与取消，随后写入提交意图并**同事务**消耗额度；
  额度争抢只有一个候选拿到名额，其余 `suppressed(daily_quota)`；触达失败不退还额度。
  attempt 以 `request_id`/`attempt_id` 幂等；旧 attempt 的晚回包只落该 attempt
  （`stale=true`），不改写候选或更新的 attempt；结果不明（超时/异常/重启）记 `unknown`，
  **绝不自动重发**，只有显式 `retry_candidate` 开启新 attempt。
  重复目标在过期后自动跳到下一个未来 occurrence，不补播错过的时段。
- **合同缺口（未虚报完成）**：已发布 `text-dialogue/v1` 只有一个出站文档

  `candidate_view()["dispatch"]` 返回 `available=false` + `contract_gap=<精确说明>`，

  带 channel message ids 时为真；测试合成适配器 `adapter="synthetic"` 即使回 `sent`，
  候选仍 `delivered=false`、`delivery_evidence="synthetic_adapter_receipt"`。
  **本任务不声称任何主动消息已真实送达。**

## 局限与下一步

1. **没有真实送达**：无已发布主动发送合同、无真实渠道。本轮只证明调度、候选与派发纪律；
   `dispatcher` 端口是唯一接入点，接入前任何候选都不得称为已送达。
2. `guard` 只覆盖 Core 本地权威事实（binding/namespace/audience/actor 角色/会话存在与隔离）；
   尚未到达 Core 的远端 Memory 撤权属于已声明缺口，本模块不声称能复核它。
   需要远端复核时应像 `repair_blocked_scope` 一样由宿主注入异步校验器。
3. 本机无 `tzdata` 也无系统 tzdb，因此**命名 IANA 时区的实际 DST 行为未在本机运行验证**
   （`life.zone` 既有约定：无 tzdb 时 IANA 名称报错，不偷偷当 UTC）。验证用测试自建的真实
   TZif v1 文件（`zoneinfo.reset_tzpath`）覆盖了缺口/回拨语义；固定偏移时区用于行为用例。
   部署环境应安装 `tzdata` 后再复验命名时区。
4. 多进程/多实例并发不在范围内（SQLite 单进程所有者）；额度与提交意图的原子性由
   单所有者事务保证，本机用例覆盖同进程内两个提交路径争抢，不构成分布式互斥证明。
5. 非周期目标过期后仍是 `active`，会持续出现在 `_materialize` 的有界扫描里；
   宿主应显式 `cancel_subject` 或重排。周期目标会自动跳到下一个未来 occurrence。
6. 文案质量与语气不由模板保证，也**不做模型改写**（这是本轮的明确取舍，不是遗漏）。
7. 迁移恢复须停机、隔离 DB/WAL/SHM 再复制完整备份；本轮只用临时合成数据库，未操作生产数据。

## 独立只读复核（本轮内）

实现稳定后另起一次独立只读复核（未修改任何文件）。复核重点与结论：

- 默认关闭与「聊天/模型不是同意」：唯一入口是显式端口，`basis` 白名单硬校验，
  无任何从 `turns`/`messages`/模型输出构造订阅、目标或提醒的路径；成立。
- `unknown` 不自动重发：`recover()` 只把 `submitted` 收口为 `unknown` 一次，
  `work()` 只挑 `ready`，`retry_candidate` 是唯一回退路径；成立。
- 晚回包归属：`owns` 判据是 `candidate["attempt"] == attempt["id"]`，
  旧 attempt 结果只写自身；成立。
- 额度原子性：`_gate` 与额度自增同在提交事务内，`BEGIN IMMEDIATE` 串行化；成立。
- 复核发现并已在本提交内修复两处：
  - 中危：订阅行的通用 `version` 曾在每次联系记账时自增，导致已排期候选被判
    `subscription_changed` 而取消（重试路径直接卡死）。已改为独立的 `config_version`
    只在真实配置变更时自增，候选按它钉住；新增失败后重试成功的回归。
  - 低危：周期目标用 `while next_due <= now` 逐次累加，长期停机时会退化为线性循环；
    已改为按 interval 直接计算下一个未来 occurrence，并让过期候选也跳档（新增回归）。
