## 2. 日志语义（本卡的核心承诺）

- **全覆盖，不采样**：`EVENTS` 是静态登记表，未登记的名字直接 `ValueError`；每次失败都记，
  不做去重或"已见过"抑制。
- **秘密不可能被顺手写入**：记录只有 11 个封闭字段，没有 message/extra/堆栈/正文位置；
  异常文本永不写日志，失败只用异常**类型**查表得到的固定标签。
- **探针纯粹只读**：`/health/live`、`/health/ready`、`/healthz` 不写记录（中间件按
  `health.PROBE_PATHS` 放行），日志目录在探针前后逐字节一致。
- **容量失败不假装就绪**：预算写满 ⇒ 业务 503 + `x-tianshu-log-capacity-exhausted:
  exhausted`，`/health/ready` 报 `logs=failed`、`not_ready`。
- **日志失败不触发重发**：写入失败不向业务抛异常，在途副作用不因日志失败而重做；容量耗尽
  在受理之前拒绝，因此不存在需要重试的东西。
- **空闲与启动噪声不记录**：空闲轮次、7 个循环的启停都不写记录。这不是省事，而是必要：
  这些记录写在进程开始服务**之前**，在通道有硬上限时（4 KiB 管道）会把启动卡死——本卡
  实测过一次（子进程停在 4034 字节、端口始终不开），去掉后同一探针 0.53 秒内就回答了。
- **受理先于副作用（R1）**：业务请求在**执行任何副作用之前**先等一次真实落盘（`await
  obs.admit(...)`）。拿不到受理就不执行业务，返回 503 与真实原因码，绝不"先做后记"。
- **终态是真实终态（R2）**：记录里的 outcome 由领域状态映射而来（`send_receipt`、
  `cancel_response`、`turn.delivery_state`、attempt 状态），映射表封闭；没有映射的领域状态
  被拒绝并计数，绝不会被写成 `succeeded`。
- **有界单写者（R3）**：所有写入只发生在适配器自己的线程里，队列有界，业务循环永不等待同步
  IO，队列满即拒绝并计数（不静默丢弃），关闭有界且不与活动句柄竞态。
- **日志失败不等于业务重做（R1/R3）**：记录写不进去时，已经在途的副作用不会被重发；业务只
  看到"日志没写成功"。

### 首验的 5 处超时：根因与同环境基线对照（R7）

首验记录为 `532 passed, 1 skipped, 95 subtests passed, 5 failed`，失败全是管理端口/CLI 连回环
端口时的 `management_unreachable` / `TimeoutError`（4 个在 `tests/test_persona_chain.py`，
1 个在 `tests/test_source_https.py`）。

**根因（本卡自身引入的产品缺陷，不是环境问题）**：未设置 `TIANSHU_LOG_DIR` 时，诊断通道是
标准错误，而 `emit()` 由**调用者线程**（通常是事件循环）**同步写**。测试用
`subprocess.PIPE` 捕获服务进程的标准错误却从不读取它，管道缓冲区写满后那次 `write` 永久
阻塞——事件循环停在 `_to_stderr` 里，此后所有请求、`/healthz`、后台轮次都不再推进，进程仍
存活（`poll=None`）但不再应答。用看门狗探针抓到的栈是
`observability._to_stderr ← submit ← emit ← RuntimeEvents._report_finished ← app.py`。
配了 `TIANSHU_LOG_DIR` 时同一序列 0.03 秒内回答，没有日志目录时才冻结——所以它只在"默认
开发路径"下发作，这正是首验与本地都踩到的那条路径。

**同环境基线对照**（`git worktree add --detach .runtime/baseline-check 17df301` 独立取出，
**解释器与可编辑安装都指向该工作树自己的 `src`**；跑完已 `git worktree remove` + `prune`，
可编辑安装已还原）：

| 运行 | 结果 |
| --- | --- |
| 基线 `17df301`，`tests/test_persona_chain.py` | **4 failed, 5 passed in 47.12s**（同样的 `management_unreachable`/`TimeoutError`） |
| 基线 `17df301`，完整套件 | 32 failed, 521 passed, 7 skipped, 95 subtests passed in 120.44s |
| 返修后本工作树，`tests/test_persona_chain.py` | **9 passed in 10.87s** |
| 返修后本工作树，完整套件 | 553 passed, 7 skipped, 95 subtests passed in 84.78s |

结论：4 个 `test_persona_chain.py` 失败在基线提交上**同样存在**，且在同一环境下用**基线自己的
源码**复现；返修后全部通过。其余 28 个基线失败是返修轮新增的用例（R1–R6 的负例）落在未修
的产品代码上，属于"新用例正确失败"，不是回归。

对照方式本身有一个必须记住的陷阱：只设 `PYTHONPATH` 而可编辑安装仍指向本工作树时，
`pytest` 会经可编辑查找器导入**本工作树**的源码，跑出来的"基线"是假的。本轮第一次对照就
踩了这个坑（当时得到"基线全绿"的假结论），已作废并用上面的方式重跑。

**必须说明**：这一缺陷由 TS-101 自己的首个候选提交引入（提交前的 `21fa99b` 没有日志适配器），
所以它**不是**"先于本卡存在的既有失败"。首版交付记录曾把它归为"环境相关、需协调者判定"，
那是错的，现已更正。

### 修复方式（产品代码，不是放宽断言）

1. 诊断通道（标准错误）改由适配器**自己的写线程**（`tianshu-log-stream`）写，与分段文件同一
   模型：有界队列 + 单写线程。
2. 该通道**设为非阻塞**（`os.set_blocking`），写不进去的记录计为 `dropped`——`emit` 永不
   等待读者，也永不抛给业务。
3. 队列满时非持久通道**丢弃并计数**，不拒绝业务：该通道本身已让进程 `not_ready`，把"没人读
   的调试流"升级成服务中断并不更诚实。持久通道仍执行严格规则（写不进去即拒绝业务 503）。
4. 顺带修掉一个真实竞态：待写计数曾在**入队之后**才发布，写线程可能在入队瞬间就完成该记录，
   于是 `flush()` / `admit()` 会读到 0 并把尚未落盘的记录报成"已到静默点"。现改为入队前发布，
   失败时回退计数。

### 真实 HTTP/TLS 与替身的区分

- **真实**：`tests/test_runtime_cli.py` 用真实子进程 + 真实回环 socket（真实 `uvicorn`），
  真实验证 owner 锁在运行期间拒绝第二个所有者、停止后释放、真实事件流写入真实文件；并用
  **真实 TLS 回环监听**验证容器健康检查脚本（受信 CA 成功、不受信失败、主机名不匹配失败）。

  `tests/test_observability.py` 用真实文件系统、真实管道与真实 `jsonschema` 校验器。
- **替身**：`/health/ready` 的 `dependencies` 本批恒为 `not_verified`；没有真实 Memory、

## 4. 风险与未完成

1. **镜像未构建**：`Dockerfile`、`.dockerignore`、健康检查脚本只做了静态检查（含"必须声明
   HEALTHCHECK / 非 root / exec 入口 / 不含凭据与模型下载"的断言），没有真实构建或启动。
   健康检查脚本本身已用真实回环 TLS 监听验证。
2. **标准错误无人读取时丢记录**：非持久通道的队列写满即丢弃并计数（`dropped`）。这是刻意的
   取舍——绝不阻塞事件循环——但意味着"用 `subprocess.PIPE` 捕获运行进程的标准错误却不读"
   这种用法会丢日志。生产应让标准错误落到运行时可读处，或用 `TIANSHU_LOG_DIR` 走文件通道。
3. **`dependencies=not_verified` 是永久的**：本批没有任何真实依赖可验证；下一张卡接真实
   Memory/网关/渠道时才可能变成 `ok`。
4. **日志预算策略是"拒绝业务"**：容量写满即 503。若运维希望"降级但继续服务"，需要新卡明确
   改这条语义，而不是在本卡里放宽。
5. **`flush()`/`admit()` 的静默点语义依赖"入队前发布待写计数"**：改动这一处会重新引入
   "尚未落盘却报已到静默点"的竞态（本轮修掉的第二个真实缺陷）。`tests/test_observability.py`
   的 `test_a_quiet_point_is_never_reported_while_a_record_is_still_queued` 锁住它。
6. **未做**：数据库迁移、网页/引擎/锁改动、真实部署、推送。
