# Memory extraction and tool quality (TS-133)

The extractor receives scoped existing fact identities and real source timestamps, preserves the source language, and returns atomic facts with time, negation, conditions and exact evidence. It rejects transient moods, third-party/fictional reports, forged authority and forgetting requests as new personal facts. Native Memory still validates and owns every write. Existing function routing is unchanged; production daily Gemini3.8 remains the default, while memory extraction follows its existing memory-function binding.

Every background attempt is reserved durably before I/O. A job has at most three attempts across process restarts, then remains blocked with its exact uncertain proposal and error instead of retrying forever. The 90-second whole-work bound covers source checks, the separately bounded 60-second model call and commit I/O. The explicit `MemoryLearning.reconcile(job_id)` recovery method only reads the existing Memory receipt after current turn permission checks. It never resets attempts or regenerates/resends a bounded-out proposal. No new network permission or anonymous recovery endpoint is added.

The `memory_propose` tool now exposes the full published target and unit shapes. Source references remain server-owned; correction/forgetting still require a recalled record/version and the existing verified proof mechanism. Replies must use actual committed/corrected/tombstoned receipts. Automatic extraction does not duplicate a source already owned by an explicit context write.
