## 实现

- 沿用 `context_relevance` 的授权后上下文选择。事实查询与同意/拒绝等表态优先保留相关人物原话、最初提议及后来的确认，避免重复追问挤掉依据。显式更正仍按不可拆分的前后文批次验证，源撤回、预算不足时不会只留下过时原计划。
- 表态查询中的个人退出单独保留，不把“不去了”扩展为整场计划更正，避免中间闲聊导致提议、确认、退出整组超预算而丢弃。同句中的真正地点/时间更正仍依赖原计划；新场景复现了原先空上下文，定向回归验证三位参与者的原话均保留。
- 同一人的紧邻省略追问可以沿前一问题的主题检索原始陈述；问题只提供检索线索，不充当事实。无关的重复追问不再作为额外填充来源，避免从提问反推作者没有听过解释。
- `qq_identity.dialogue_sources` 在既有来源视图中标记当前提问者、其他参与者以及每句原话的第一人称归属；消息时间明确标为消息元数据，不当作事件时间。用户原话仍仅进入不可信数据部分，不通过名字、引文或模型文本授予权限。
- 自动抽取队列保存事件的准确 scope 和 turn sequence。同角色、人物、受众、会话中的后续任务等待前序 pending 抽取；更早的 outbox 接收回执仍未知时也等待。其他 scope 可继续处理。旧 pending 行分批补齐顺序，保留原重试次数、期限和不确定提案。
- 每次最多读取 64 项到期抽取任务，以内存游标轮转，前序检查使用派生索引。数据库结构版本不变；缺少新索引时复用 `work_index` 的迁移前 SQLite backup，恢复点包括 WAL。没有新增事实表或另建记忆系统。
- 上下文准备时，独立的历史读取及画像读取按最多 4 个并发执行，按原目标顺序装入原上下文预算；取消时回收所有子请求。后续模型调用和发送检查仍重新核验来源，不能复用准备阶段的旧结果。
- 仅自动抽取的生成请求带 `reasoning_effort=low`、`max_tokens=8192`，使用既有 memory 功能模型绑定。普通聊天请求没有这两个新增参数，日常 Gemini 配置未修改。原 60 秒模型期限、6 次持久重试上限、未知提交先查回执和原提案恢复保留。
- 回执读取复用 `JsonService` 的有界断连重试，严格限定候选处理端点、非空 job_id、`output=null` 和精确两个字段。它修复了一次 3 毫秒旧连接失败造成额外 120 秒退避的问题；带提案的写请求、额外字段或缺字段均不自动重发。HTTP 503 仍交给已有持久恢复流程。
- 抽取区分行为与其建立的可检索状态：有明确保存用途的物品位置可以记为当前位置，不推断永久习惯；有时间/地点/协调信息的未来会面提议可以保存，维持提议身份，不当成全群共识。集合暗号作为数据保留；取用、清洗以及明确临时放置仍留在短上下文。

DeepSeek 当前支持的请求参数见 [官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)；OpenCode Go 的 DeepSeek 路径见 [官方文档](https://docs.opencode.ai/docs/go/)。本机隔离 broker 校验实际模型为 `deepseek-v4.1-flash`，逐次登记累计账本，实际请求参数另有记录。
