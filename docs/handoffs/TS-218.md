## 实现归属

- `context_checks.VerificationCheckpoint` 管理一次新鲜核验中的四路读取和精确去重。Core 在续办当前来源后，重叠授权、管理员状态、当前记忆快照、继承材料和陪读状态检查。每个模型前及发送前边界新建检查点；不同来源租约不按同一人物合并，每个历史来源仍检查本地作者、渠道、绑定和版本。
- 复用 `read_parallel` / `verify_checks`，任一读取失败立即取消并等待其他任务收尾；不让失败的准备继续等待慢检查，不产生跨轮次权限缓存。
- `context_time` 负责最终模型时间投影。保留人类原文、作者、顺序、来源引用和必要的已发送助手回复；普通事实问题移除重复的原始消息钟点。明确询问消息钟点/日期等问题时，在独立 `transport_clock` 中提供带偏移量的系统时间。原话时间词以精确跨度标注为自述，不推算事件日期、时区或实体生效范围。
- 存储和核验继续使用原始消息，不修改数据库时间。模型提示的实际字节数按渲染后内容记录，材料接纳仍使用原始来源的保守预算。归属指令继续位于 `qq_identity.SOURCE_INSTRUCTION`，Core 仅装配。
- `JsonService` 对既有查询白名单补充 HTTP 408 / `timeout`，只有同时明确 `not_started` 和 `retryable=true` 才可恢复。继续使用两次尝试、十五秒查询总预算及原有有界准备恢复；写命令、执行状态未知或缺失、不可重试响应均不重放。
