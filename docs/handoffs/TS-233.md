## 变更与复用

1. 复用共享 StorageOptions/StorageRuntime/连接池/FileStore；没有复制共享包或添加导入回退。默认 SQLite；独立 PG URL 与本地 `database_path` 锚点分开。Companion main/启用的 observations 同组完成激活；NoneBot journal/rpc 可独立配置、各有逻辑 schema。
2. 产品原生 PG schema/import 在 `storage_postgres.py`、`observation_postgres.py` 和 NoneBot `storage.py`。canonical body 保留 TEXT；JSON 查询转为有类型的 jsonb 表达式，数组展开、部分/表达式索引、identity rowid、序列、C 排序与事务语义均有实现。导入逐行校验所有字段摘要、数量和 rowid 顺序；媒体/素材验证重建等价后提交引用。同名未知/漂移索引拒绝启动。
3. 保留 Store 最外层事务/source_head、CAS、来源、轮次、outbox、幂等和 unknown 规则；PG session advisory lock 仍只允许一个运行时。连接丢失不透明续事务或重放写入，需恢复连接后重启进程、重新取得 owner 并按旧恢复逻辑对账。关闭和激活失败显式释放 checked-out 连接/owner；PG 已激活后缺配置或断线不能写回旧 SQLite。
4. `PayloadFiles` 只外置 `replies.v2_request` 的 base64 媒体和至少 64 KiB 的 `write_materials.material`。文件先提交，SQL 保存引用与原 wire 摘要；读取核对哈希/大小并重建请求。表示转换不推进 source_head。日记、人格和人工原创章节及修订仍在 SQL；没有自动删除恢复材料。
5. NoneBot 旧 pull Journal、RPC、OneBot 主机配置均接入。`--show-key`、RPC show-key 与 `scripts/inspect_state.py --storage-config` 通过共享只读入口读取当前绑定，不迁移、不建标记/测试键、不回看旧 SQLite。SDK claimed/inflight→unknown、回执、事件排序和 ACK 规则保持。共享 RPC canonical 与 NoneBot/AstrBot 两份分发副本逐字节一致；AstrBot 默认账本仍为 SQLite。
6. 两个 Dockerfile、产品依赖及独立 NoneBot wheel builder 均使用固定共享 wheel。builder 同时输出 storage wheel，NoneBot wheel 显式声明固定依赖；未留下共享开发 worktree 路径。配置和安装/恢复说明见 [storage-backends.md](../storage-backends.md)。
7. Redis 配置由公共层识别；本产品没有新增业务 Redis 缓存，模型槽位、核验检查点、短期上下文及所有权威事实保持原语义。
