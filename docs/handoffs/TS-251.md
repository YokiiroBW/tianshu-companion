# TS-251：回应对象、时间来源与明确限流恢复

本卡只在独立 worktree 本地实现，基线为已发布 Q15 Companion `5f569c7bc71a9beef7d9c2ee45d4a5d17daf0f41`。未合入、推送或部署，未调用实际模型、NAS、QQ 或通知，没有读取真实用户记忆或修改共享合同。

## 改动归属

- 复用 `qq_identity.dialogue_sources` 的原生来源投影，增加当前请求、延续片段和其他轮来源的区别。其他作者并发问题、同作者历史问题保留原文及人物归属；它们不会仅因进入上下文成为本轮任务，当前输入仍可明确引用并要求回答。投递阶段明确是选取上下文时的快照，确认发送段数仅表示交付，不能冒称问题已解决。
- `short_context.select_recent` 保留实际确认交付段数；`context_relevance.input_only` 统一原有两条省略助手旧答的路径，省略正文时保留交付事实及省略标记，不删除他人输入、不新增来源或权限。
- 在现有 `context_time` 中集中区分事件归属、传输时间、自述钟点核验及当前时刻。只有真正时间核验展示标明来源的传输时钟；当前时刻取准备上下文后的 Core 时钟观察，不沿用入站时刻。不推测时区或日历日期；数量词“一点”、地点与普通事实核验不会成为钟点。
- `Completion` 仅识别精确 `error.type=rate_limit_error`，混合 choices/content/tool_calls/finish_reason 字段的错误帧拒绝，包含空值也不忽略。`Gateway.complete` 先耗尽/关闭流，再用现有路由查询同 request/config/caller 的终态回执，整体最多等一秒、最多三次逻辑只读查询。只有 failed/failed/upstream_http_error、upstream_started=true、cancel_requested=false 且无 finish reasons 才给内部恢复标记；不会伪称 not_started。
- `Core._respond_native` 复用原有一次 `model_connection_retries`，仅初始迭代/初次尝试、没有工具增量/完成结果、持久 expression/native_execution 或任何本轮 reply、没有取消或撤权时恢复。明确拒绝下可重建本地 `Segments` 丢弃尚未发送的文字，之后重新检查角色、来源与模型租约。普通断流或 unknown 仍保留原来的无输出边界；任何已发、未知、在途或待发的持久意图都不会重放。
- 一并修复原有重试路径的等待竞态：来源核验 await 期间已经持久化的取消/终态不能被旧对象覆盖。核验返回后在同步事务内重新读取本轮，再核对终态、发送意图、来源版本、角色和租约，最后才递增并保存最新对象的调用次数；事务不跨 await。此问题经合成实际 Core 路径复现，不表示已在线发生。
