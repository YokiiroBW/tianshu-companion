# TS-307：规范证据、长期原话与有界复验

基线 `b84265379566fdb07916949533bf28a2781e06eb`，分支 `codex/ts-307-memory-core-q21`。本卡为隔离本地候选，尚未合 main、推送、部署或实际用户验收。根合同、任务板、Memory、QA、真实 PG/模型/设备均由协调者或其指定写者维护。

## 实现

- 新 job 读取显式协商 `[3,4]`，在生成前持久化 Memory 的实际 schema pin。旧 ACK 丢失但已锁3的 job 可以明确恢复；无 pin 旧持久提案仍走旧请求，未知提交不换协议、不重新生成。schema4 提示从发布 Registry 内联 output 引用，不复制合同；至多32个规范原子提案、精确证据和 target_refs。计划/实际以 modality 区分，schema4 不再用旧中文空结果补抽规则。Memory 仍是唯一事实和写入回执权威。
- 正常准备调用 v2 query，默认单个 mixed 子查询、全局8 facts+8 episodes；客户端也支持最多4个合同子查询。完整 evidence、group/record versions、episode span/hash、scope 与预算逐项核对。原短期对话/画像/关系材料保留，规范 `memory_state` 与长期 `episodes` 同时装配，区别源观测时间、事实有效时间、计划与已观察事件。
- v2 verify 将原 select/history/input_history/profile 请求及期待值合批；64是单个 wire 包的上限，超过64的必需依赖完整拆批，全部通过才生成/发送。每个完整检查集合 fresh barrier，历史作者续租不会复用旧 Memory proof。Core 原作者/物理来源/渠道/绑定/续租、角色、管理员、陪读及发送资格检查保持；流回执、unknown 和原槽位/队列不改。
- `context.bound_recent_provenance` 限制可选回复的来源闭包在本次已选组与必需依赖内。跨窗旧回复切换到已有完整 input_only 变体，保留人话、标记省略回复，避免每轮递归带入全历史。显式方案和续写依赖不裁剪。v1保留原可选上下文64项预算，避免兼容路径退化。
- 记忆工具更新成功后的 v2 路径复用 `_prepare_context` 重装全部材料和检查，避免只换事实却遗留未经验证的旧回复或画像。普通回复没有新增审核模型。

## 来源级遗忘回执说明

Memory 的 episode 遗忘复用旧回执时，`record_ids/group_ids` 可以为空；其完成目标由原操作的 `kind=forget_episode`、精确 episode target 和 `tombstoned` 状态绑定，实际失效范围为该原话的整个来源及派生记忆。Companion 首次调用和恢复路径均已接受空数组、按成功状态刷新全部材料，不需更改流程。仅修正自动记忆提示中把所有操作都解释为 `record_ids` 的旧表述；普通记录操作仍以回执 ID 为准，unknown/rejected 不宣称完成。

现有 episode 成功/未知恢复及对话状态影响集 **7 passed、59 deselected**，1.07秒，日志 `.runtime/q21-source-forget-prompt.txt`；单文件 ruff/format 与 diff whitespace 通过。未新增模型调用、测试门槛或共享合同，未重复全部测试；这是回执解释修正，不代表来源闭包或整体验收已经完成。
