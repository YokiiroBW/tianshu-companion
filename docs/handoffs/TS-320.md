## 实现与复用

- `integrations/shared/participation.py` 在原 AdapterService 同一 SQL owner/锁中扩展观察附表：全 native 唯一归属、结构化成功收据、候选/决定/派发前登记、不可变领取结果及原 connection/reply/attempt 绑定。七个新 RPC 操作使用独立 `/participation/` 命名空间，旧 poll/ACK/messages/send/status DTO 不扩字段。
- 同 request_id 先查原回执，异参 conflict，同参原 grant 与当前有效性分开；ACK 不释放，重启/代际/到期/新 abstain 使当前领取失效。候选首个期限固定，不续期。观察清理在原事务删除关联，并保留最小 native 摘要、旧参与命令身份和 request 摘要，防止删除后 SDK 重放重新 free 或晚到参与命令降级普通发送；不保留已删正文或原行引用。
- 原发送入口先查历史 deliveries，再核参与 binding、账号/群/turn/attempt、当前 claim、来源 confirmed；真正调用原 sender 前再次核验。pending 绑定不能发送；仅允许同一绑定 pending→confirmed，不新建 sender/队列，unknown 不自动重发。
- NoneBot `participation_host.py` 只在实际 `onebot.create_host` 独立构造后启用，限定 NoneBot 2.5.0 / OneBot 2.4.0 和准确注册集合。公共 event/run hook 与事件级 Depends 收尾结合一次真实 `_observe`、`_claim_observation_reply`、`_scope` 的持久收据；不重复运行 filter、不 monkeypatch 框架。实际其他 matcher 入场即 handled；不明图、异常、取消、缺失收据未知。普通消息没有语义消费者时保持静默。
- AstrBot 4.27.3 普通消息仅未知归属，不能签发自动 claim；原显式路径保留。版本无法确认时不冒称可用。
- canonical 与 NoneBot/AstrBot 三个发行模块逐字节一致。原 `storage.prepare` 仅允许已有合法 ready schema 补建本卡附表；不放宽原业务表/version/source 校验。
