## 宿主接口

```python
build_runtime(config, *, internal_clients=None, environ=None, log_adapter=None)
create_app(core=None, tokens=None, life_readers=None, *,
           config=None, config_path=None, internal_clients=None,
           environ=None, log_adapter=None)
```

`config` 与 `config_path` 是显式替代输入；原无参数 CLI factory 仍读取 `TIANSHU_COMPANION_CONFIG`。部署 database/contracts 仍沿原显式环境覆盖规则，配置文档不被修改。传入的 `environ` 同时供应 service/caller/persona/diagnostics 凭据、StorageOptions 和旧静态 ComfyUI token；不轮流覆盖进程 `os.environ`。共享存储原 `StorageOptions.from_settings(..., environ=...)` 已提供该能力，直接复用。

`internal_clients` 接受协调根 `LocalExchange` 对象，仅按下面明确业务归属调用 `async_transport(target)`，不按 URL 选择模块。工厂可先取得 transport，随后宿主注册所有应用；实际请求由 exchange 核验目标及登记 origin。原 HTTPS 配置、CA 路径与 bearer 验证仍保留；内部 ASGI scope 为真实 `http`，不伪造 TLS 或身份头。Companion 服务端原先没有要求 scheme=https 的判断，因此没有增加 TLS 例外或第二套授权。

| 配置接点 | 明确目标 |
| --- | --- |
| platform_sender、provider_selector、provider_selector_background、qq_admin、actor_memory_authority、image_credentials | platform |
| 已登记 platform caller 的 origin_service 别名 | platform |
| memory | memory |
| knowledge | knowledge |
| gateway、gateway_background | gateway |
| nonebot、其来源服务、chat_history、ComfyUI | 原真实网络 |

显式 knowledge 继续保留独立 JsonService、凭据与查询容量；旧未配置 knowledge 的部署仍用独立 JsonService 访问 Memory，保留其原凭据与独立回调容量。没有把 Knowledge 合并成 Memory 客户端实例。

`log_adapter` 由组合根注入 Core 与各 JsonService，绑定自己的事件实例；原维护脚本/测试的默认事件端口兼容保留。未注入时 `log_adapter_from_environment(environ)` 沿原日志机制创建实例，工厂失败会关闭自己新建的日志写者。日志 admission、故障与 durability 规则不变。

## 停止次序

`app.state.lifecycle` 提供两个宿主接点：

1. `await lifecycle.quiesce()`：标记 workers 停止、结束周期 producer 的下一轮、拒绝新的根命令；当前 pass 不被提前取消，来源/lease/receipt/read 与 cancel 仍可达，clients/Store 保持打开。
2. `await lifecycle.drain(timeout=30)`：先等当前 producer pass 与已受理根请求，再请原 Core/MemoryLearning/Life 任务所有者等待自己的在途任务。返回 true 表示已收尾；期限后复用原取消逻辑并等 finally 完成，返回 false，仍不关闭 Store 或客户端。重复或取消等待者不会重新启动另一轮 drain。

宿主应先停止所有模块的新 producer/root admission，在 exchange **仍 open** 时完成各模块 drain，再 `exchange.close()` 进入原 lifespan 最终关闭。最终仍按 Core 业务任务、image backend、Store/storage、配置客户端、终态日志/日志写者的归属顺序释放。不能先把 exchange 标为 closing：独立后台任务的合法出站调用没有原入站请求的重入上下文，会被拒绝。持久排队工作不强行跑空，沿原 recover 恢复。

本卡只在 Companion 本身区分新根命令与来源回调，不创造跨模块 root 传播字段。宿主若需要让已在途 Platform 根流程在 quiesce 后首次进入 Companion.ingest，需在整体 admission/drain 排序中处理，不能把所有 `exchange.owns` 请求都当作已经受理的根请求。
