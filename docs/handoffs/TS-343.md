一个进程只构造一个自有 OneBot app。已存在的 NoneBot driver 不会被重置或重新注册，重复 factory 明确报错；失败的自有构造会关闭已打开的 SQL owner。原 SDK token 和持久 Platform access_key/instance_id 保留。生命周期只暴露原 instance_id 的只读字符串，不提供 access_key 或数据库对象；协调者按此身份绑定 Platform 内置连接，不按 URL 或 adapter kind 猜本地。

内部 exchange 和公开监听复用同一 app，必须只驱动一次原 ASGI lifespan；例如 exchange 的 owner 已进入 lifespan 时，外部 ASGI listener 使用 `lifespan="off"`。在当前固定 NoneBot 2.5.0 源码中，FastAPI driver 的 `_lifespan_manager` 明确调用原 `_lifespan.startup()/shutdown()`，启动/关闭钩子属于原 driver；本卡没有复制或替换 SDK 的生命周期机制。

## 停机合同

1. `await lifecycle.quiesce()` 停止新 SDK 事件进入；已接受事件跨 matcher 的观察/声明/最终 closure 保持。合法的发送、状态和 ACK RPC 仍可进入，原 service.lock、15 秒 SDK send、20 秒 service.handle 预算和回执规则保留。
2. 其他模块停止新 producer 并完成在途调用期间，保留公开 WebSocket/API 回包通道。随后 `await lifecycle.drain(timeout=20)` 等所有已接受 RPC 和事件完成；True 只表示当次真实操作归零，False 表示等待超时，既不取消任务也不关闭 DB。取消等待者同样不释放操作，允许再次等。
3. 最终退出原 ASGI lifespan：driver shutdown 关闭新 RPC 准入，等待真实完成后执行原 unregister/SQL close。同步 unregister 在空闲时仍可用且重复安全；有在途操作时明确要求先 drain，不提前关闭其数据库。

NoneBot 的 lifetime dependency 可能在短命预处理子任务中进入、由主事件 AsyncExitStack 执行 finally；只 gather 初始 task 会误判完成。本卡用每操作完成 Future 跟踪直到 finally 真正写完，等待被取消不影响 Future。参与权图、matcher/processor、closure 判定和发送账本没有另建路径。

总退出期限由外层宿主持有；drain 不保证整个 SDK/默认 executor 的所有任务为空，也不关闭外部 SDK 正在使用的 WebSocket。最终正常 hook 等真实归零，强制超时由进程级 owner 处理并准确报告未完成。原取消/中断留下的 inflight 仍在重启时恢复 unknown，不能当未发送重发。没有为减少服务擅自改变 SQL 或 NAS 文件权限。
