## Result and ownership

- Original Life diaries/materials/revisions, recipe, draft and publish pointer still own every prose body. `diary_materials.py` composes actual actor episodes in a fixed civil-day UTC window, distinguishes digital action/observation/fiction, captures persona, preserves occurrence/learning/coverage and marks incomplete selection. No new user-memory table, algorithm or API, no extra per-dialogue planner/model slot.
- Source-backed generation returns content plus separately sourced reflection/understanding/preference and questions. Derived records use the existing `append_validated_derived` receipts with original episode references; questions use original autonomous concerns. An unknown derived acknowledgement resumes the same stored conclusions/keys without regenerating or relearning diary prose.
- `diary_disclosure.py` renews actual Knowledge read/disclosure proof before creating a clean public-original projection in existing actor source/outbox records. Old actor-only sources remain unchanged. Projection excludes private motives/query, preserves old occurred_at and records new learned_at. Every source callback renews original read and disclosure version; no unproven legacy acquisition is upgraded.
- `diary_sharing.py` uses real active Proactive subscription and a neutral paused motive to obtain a real current audience assertion. Public webpage drafts and each exact-scope share draft are independently generated from filtered material. Scoped drafts never get a public publish pointer; the existing motive alone is activated with its verified text. Existing quiet/cooldown/quota/outbound and unknown receipts remain authoritative. No subscription yields only a private diary.
- Generation before/after, commit, publication, LifeRead HTTP list/revision, direct read/admin-read, proactive expression and actual send all recheck source basis. New asynchronous verified read methods cover source-backed content; synchronous legacy entry points reject it. Old fictional diaries remain readable. Public responses expose only the frozen provenance marker, never private proof/material.
- AL06 planning filters withdrawn source-backed concerns/current or previous activities before using their text; model-slot and post-generation checks reject a withdrawal race. Activity continuation also persists and checks the concern basis behind cached prompts.
- Existing ActorMemorySkill supports `day: yesterday|ISO-date`, or fixed `window`/`cursor` continuation. Default query is unchanged; incomplete/omitted/pending actor outbox cannot mean no experiences. User and actor evidence remain separate.
