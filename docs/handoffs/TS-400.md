## 实现

- `conversation_windows.py` 拥有原 metadata 中按规范化 conversation/actor/audience/private person 隔离的窗口、增量计数、有界历史分页、轻量多维触发、后台 work/recover/drain/close 和 platform 认证的 status/clear。
- `conversation_window_compaction.py` 拥有一次有界压缩与执行状态：完整旧前缀、原来源/历史快照核验、真实 sent 回复、背景模型槽与既有 model_selection/Gateway、派发前持久 ID、持久 result 后核验提交、unknown 回执恢复。成功 receipt 留作精简执行记录；不删除原文、不重复向 Memory 学习。
- Core 在拿前台模型槽前触发硬整理，在原 TurnContext/近期材料准备处注入摘要；app 原配置及后台 lifespan 已接线。空闲时还核对未封盘收件和活动 turn，获得背景槽后再次让位。
- Gateway.complete 增可选 `request_id`，新增只读 `receipt`，复用原校验，不改变 server wire、授权或路由。旧 generate-only 端口明确降级 `dependency_unavailable`，不会令聊天失败。
- 参数、管理请求及局限见 `docs/conversation-windows.md`。本地管理 wire 无 Platform 页面消费，不声称 QQ `/reset` 已提供。正常单槽在途背景不可抢占；摘要语义未经过真实模型验收。
