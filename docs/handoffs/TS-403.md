# TS-403 Companion / SDK 链路质量审查与修复

基线 `a22924323a6b1b28ab166833df165cf96e351b6e`；分支 `codex/ts403-companion-chain-quality-20261029`。仅本地隔离修改与提交，协调者负责集成、推送及发布。

## 确认问题与修复

1. 主动表达在等待模型时管理端取消候选，随后模型异常会用生成前旧行覆盖取消，恢复成 unknown 并丢失取消原因。`Proactive._expression_unknown` 重新读取同一次表达尝试，保留最新取消/终态；任务取消同样持久结算，不吞 CancelledError。
2. 重启遗留 `expression_state=generating` 原先会再次生成。原单 worker 锁内每轮最多处理一个无活跃所有者的生成意图，保留 unknown，需要显式重试；先于图片准备处理，覆盖生成已落图片意图但尚未落表达完成的中断点。未增加调度器、恢复队列或全库启动扫描。
3. 主动表达采用 `Memory.select` 的收件人记忆后，仅复核动机自身来源，遗漏所采用记忆的撤回/版本变化。仅实际采用非空 selected_units 时保存内部 `memory_context_check`：scope、scope_version、association_version、scope_checks，不存新增记忆正文。复用原 Memory.select 零预算 known 校验及 RuntimeExecution.validate_sources，在生成前后、真正发送前和原图片准备边界复核。无记忆采用路径不增加校验请求；无新 wire、Memory Store 访问或用户记忆语义变化。

## 静态覆盖与保留决策

- 入口：SDK group_policy/participation、NoneBot RPC 与事件生命周期；群 disabled/observe/reply/active、明确呼唤/关键词、私聊策略保持；Web/QQ 继续原来源与 sender 边界。
- 普通对话：Core、context_preparation/context_checks、source_sync、collector 到生成、preflight、投递/unknown 查询；未更改原模型准入、来源撤回语义或恢复键。
- 会话窗口：conversation_windows 与 compaction 的持久作业、来源版本、水位和 retained tail。暂不可用摘要有原始历史 floor 回退，不误判为丢历史；明确 reset generation 仍隔离旧窗口。
- 用户记忆：memory_learning、memory_segments 的原分段/commit_wait/回执恢复、同 scope 前序与轮转让位；旧提取路径已在基线退役，本轮不复活。ActorMemory outbox 保持原键与执行状态区别，unknown 不伪作未执行。
- 日程/自主活动：Proactive 状态、并发取消、原恢复；Life per-actor/phase 轮转、activity marker/checkpoint、autonomy 来源、阅读与旁听入口；写作章回、日记/反思/分享仍复用原 owner。发现的主动表达缺口在以上原归属修复。
- 生命周期：RuntimeLifecycle.quiesce 停 admission/producer，producer 的 stopping.wait 可唤醒；Core.drain 等有限 jobs、发送、MemoryLearning/Life/window。SDK AdapterLifecycle.pending 跟踪 RPC/事件完成 Future，不包含 OneBot WS 连接；旧 runtime._loop 在 close 先取消。未从本域静态证据确认根报告的约 120 秒停机因果，已建议根核公共 WS ingress drain；没有改 timeout 或强杀。
- 废弃代码：未确认新的无调用且无迁移用途实现，因此未删除。未以静态审查宣称整个系统没有缺陷，未扫描无关媒体内部。
