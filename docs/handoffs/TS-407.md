# TS-407 会话窗口恢复

基线 `5b83948c507fba97a496cfda1acff882816aff7f`，分支 `codex/ts407-runtime-recovery-20261029`。仅两份 window 实现及对应测试；未写 Core、context_checks、Store、Memory、学习或日程。无合同、DDL、依赖变化，未合 main、推送或操作生产。

## 证据与根因

根只读实测同一窗口约 7 分钟 generation 从 7544 增至 7740，last_activity 不变、counts=0、last_error=scope_changed。

压缩原调用 `Core._verify_checks(anchor, authorities)`，即使 authorities 为空也会在 v2 anchor 上进入 AdoptedChecks → `_refresh_preparation_origin` → `_check_preparation_origin` → `_check_input_versions`。它核验的是历史聊天整轮上下文，其中 `conversation_windows.verify_local` 要求历史 `conversation_window.generation` 等于当前窗口。一次 reset 后旧 generation 必然不符，压缩又将该 scope_changed 当来源撤回 reset，下一轮 bootstrap 重新加载相同输入，形成自激循环。历史短上下文过期也属于不该用于新窗口重建的整轮前置条件。

新增回归由既有 CoreEvidenceTests 的 v2 端口驱动真实 Core 生成已完成聊天，保留完整 memory_context。窗口代数改变后，直接调用旧入口 `_verify_checks(anchor, [])` 确认抛出 scope_changed；修复路径随后正常重建，没有删除 anchor 字段或改造其身份。该测试证明机制，不宣称读取了生产聊天正文或唯一确定第一次 reset 的远端原因。

## 改动

- Window 的 `verify_materials` 组合原 `context_checks.verify_checks` 与 Core `_verify_context_check`，只核实际采用的材料：每位原作者的租约续期、授权、精确输入来源、历史水位、已采用回复依赖。仍使用原 Memory source-sync/history/context/profile 端口；不重新要求历史聊天当时采用的旧窗口或其他未采用上下文仍有效。
- 捕获、模型前、提交和摘要读取使用同一材料核验路径。回复若旧窗口证明失效仍不作为记住的发言；原始输入须单独通过真实来源核验。
- 已有摘要的权威确定失效仍 reset 一次，丢弃旧摘要；无摘要的来源读取失败不再不停制造 generation 或清空 raw 计数。unknown 和续期失败不被当成明确撤回。
- 同一失败捕获使用当前窗口内的无正文 signature、stage/code、source_invalid/dependency_invalid/renewal_failed 与既有 cooldown 重试。新输入、源代数或窗口版本改变可重新尝试；原材料和 floor/covered 保留。此退避只处理尚不可读的来源；解除正常 v2 重建自锁靠材料核验职责修正，不靠加睡眠掩盖。
- 原模型 request_id、unknown 回执恢复与已收到但未提交的结果恢复不变。明确失效的结果不提交；暂不可用的结果保留等待原权威恢复。

## 发布后只读观察与边界

无需改生产窗口 floor、清 metadata 或手动改 generation；原窗口可在下一次有资格的 worker pass 用原始材料重建。若真实来源仍不可读，保留 last_error 与 capture_failure 机器诊断、等待现有冷却或输入/来源变化；不能承诺一定生成摘要。旧 generation 留下的历史 metadata 未在本轮删除。
