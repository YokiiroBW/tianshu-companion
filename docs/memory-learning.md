# 自动记忆整理

自动整理只使用当前多人会话协议 schema 6。已送达对话和仅观察消息先登记材料，再由现有后台队列分批整理；聊天投递不等待整理完成。单人摘要 schema 5、结构化自动事实抽取 schema 2/3/4、语义规则补抽和旧协议协商已经退役，没有备用写入链。

## 材料与分段

Core 送达后的原事件通过 `/internal/v1/memory/candidates/materials` 交给 Memory。Core 只保存原不可变请求及材料回执，重启或响应丢失时仍使用同一请求；有界 backfill 每轮最多检查 64 条已送达 outbox，补齐当前材料回执的交接，不恢复旧提取任务。

同一角色、会话和受众的材料进入现有 metadata 队列。安静 120 秒后封段，持续发言最多等待 600 秒；单段最多 32 条消息、8 位目标人物和 48 KiB 原话，超限另起下一段，不截断人的新发言。不同会话和角色不混段，重复回执不延长安静期限。群上下文可以包含本群其他人物的发言与来源可证明的 BOT 回复，私聊上下文仍精确限定 scope。

封段、读取已冻结窗口、模型整理和提交是独立的持久阶段，共用原有 worker、模型槽位和公平调度。模型只在拿到当前来源与授权证明后运行；前台优先，后台在既有有界容量内继续进展。没有新队列或独立任务调度器。

## 一次整理多人

每段用一次 `function_id=memory` 模型请求结合完整上下文理解各人的表达。结构化输出按真实 person ID 分组，包含覆盖消息、经历或安排、实际状态、重要程度、保留期限以及可选画像；不单独为每个人、重要程度或画像再调用一次模型。

每位目标必须返回一次完整覆盖；`memories=[]` 是合法结果。其他人的话和 BOT 回复可以辅助理解，不能单凭这些内容断言目标做过、同意过或已经完成某事。证据不足时保留不确定性或不生成个人记忆，不补关键词规则强行归类。相似的经历可能发生在不同时刻，不因文字相似就合并或跳过。

模型提出内容，Memory 负责人物、scope、源版本、覆盖、精确 prior 引用、原子提交和最终回执。画像只能以该人的原话为个人证据。手工记忆工具、明确更正和遗忘仍走现有 Memory 权威接口，不经过自动整理器。

## 重试与状态

任务在 metadata 中保存原窗口、输出、模型路由、阶段和有界重试预算。未知提交或丢失回包先查原回执；已提交输出不因重启而重新生成。没有有效输出的模型/结构失败按既有冷却和次数上限恢复，达到上限保持 blocked；显式 reconcile 只查询回执，不重新生成或无限追加模型请求。

创建段和提交输出可能写入远端，继续使用来源与前台的写入协调。已知 job 的空输出请求仅查询窗口或回执，不安装新的写入屏障。模型使用独立 provider 会话及已绑定的后台配置，不借用前台授权；静态配置仍沿用现有配置入口。

`automatic_memory_candidates=false` 暂停当前自动材料提交和整理，保留当前积压。启动后发现的旧协议 pending/blocked 条目每轮最多 64 条标记 retired；不调用远端、不调模型、不伪造 completed，也不阻挡当前段。清完即停止本进程的旧条目探查。旧数据无需迁移为新记忆。

completed 表示取得实际处理回执，可能是保存，也可能是全部跳过，不能据此宣称新增了记忆或画像。运行能力端口只展示当前队列与回执状态，不将旧条目混入当前 blocked 或整理成功信息，不自动宣称已完成真实环境验收。

## 验证范围

当前自动流程的隔离用例在 `tests/test_memory_segments.py`；后台配置分离在 `tests/test_generation_context.py`，来源提交和未知回执在 `tests/test_memory_candidates.py`、`tests/test_memory_v2.py` 及定向传输用例。仅适用当前改动的用例需要运行；这些替身验证不证明真实 QQ 收发、真实模型质量或生产吞吐。
