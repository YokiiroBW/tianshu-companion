# 自动记忆闭环

正常对话沿用原有来源记录和候选 outbox。候选受理后，`MemoryLearning` 在现有 metadata 持久队列中登记候选 job，独立后台循环每秒取一条到期工作，不在聊天投递锁内等待模型。既有已受理候选通过有界 rowid 游标补入，每轮最多检查 64 条。

TS-165 起，抽取与生活任务使用同一后台模型容量，合计最多一个活动请求；聊天优先且后台保留进展机会。总并发、持久恢复与模型选择沿用现有配置，具体调度和重新核验规则见 `query-transport.md`。这不表示候选任务完成前聊天必须等待，也不表示所有完成任务都会写入事实。

抽取完成后，如果该角色还有正在准备、生成或投递的对话，原提议以 `commit_wait` 保存，先让这些回复结束，再提交记忆。等候期间该角色的新轮次留在原有队列，其他角色照常处理；按角色协调也覆盖显式关联的记忆范围。提交后解除等待，新轮次从当前版本读取快照。这避免后台新增事实恰好改变正在生成回复的版本，使回复因 `scope_changed` 被自身整理中止；模型前与发送前的版本核验继续保留。

TS-171：精确的空提议 `{"memories": []}` 可直接交 Memory 核验并记录 skipped 回执，不占上述角色提交等待窗口。空提议不产生内容版本变更，仍检查当前来源、权限和候选状态；非空或格式未确认的提议继续等活动对话结束。已持久化的空提议在重启后的等待恢复也沿用这一规则，不重新调用模型。

`commit_wait` 延续已经预留的尝试，不追加模型请求、重试次数或空闲持久写；重启后保留提议并先查回执。真正的调用失败仍使用原有有界恢复，等待提交不会把失败变成成功。协调只覆盖本进程自动抽取：外部修订、遗忘、撤权或未知远端提交仍可让进行中的回复按原核验终止。

处理顺序：读取 Memory 回执/当前来源 → 选择 `function_id=memory` 模型 → 提炼带精确引文的事实 → 持久保存原提议 → Memory 再核验与提交 → 保存回执。模型选择复用原功能配置与默认回退，未启用动态选择的部署沿用固定配置版本。抽取与聊天使用独立 provider 会话，避免提炼提示或 JSON 污染聊天历史。模型输出仅为 inferred，不生成权限、身份绑定或关系分数。

现有 `automatic_memory_candidates=false` 同时暂停候选投递和整理，不删除积压。来源和授权由 Memory 在读取及提交时核验。后台每轮预算 90 秒，自动抽取生成等待预算 30 秒，取消清理仍包含在工作总预算内；单独回执恢复最多 45 秒。临时失败前两次分别等待 2、4 秒；模型/提议阶段尚无有效提案时，随后等待 8、16、32 秒；其他阶段第三次起仍冷却 60、120、240 秒。总尝试最多 6 次，累计三次明确无效提议或权限/来源拒绝提前停止。尝试次数、处理阶段、恢复原因及原提议持久保存，重启不重置额度；旧版本三次后 blocked 的临时失败通过有界游标补入冷却队列。

写入无响应时保留原提议，先查询回执；只有 Memory 明确 rejected 才丢弃提议重新生成。恢复时重新核验来源和角色，重新生成使用当前获准的 memory 功能模型；不重放聊天。全部尝试耗尽后仍保留 blocked 和提议，内部 reconcile 只查回执，不无限追加模型调用。候选受理 outbox 的 unknown 也按相同不可变事件重放，复用服务端幂等，不重发聊天消息。

TS-202：读取 Memory 当前来源后，`memory_admission` 只对每个分句都能判定为纯询问或寒暄的输入生成空提议，仍交 Memory 做来源/范围核验并取得真实 skipped 回执。含陈述的混合句、引号内名称、提议、更正、同意/退出及其他不确定文本仍调用原抽取器，显式记忆工具不经过这个过滤器。判定原因留在本地任务 `admission_reason`，不把跳过称为保存成功。

自动抽取首次单独使用 `max_tokens=8192, reasoning_effort=none`，已用现有 OpenCode DeepSeek 接口验证；明确无效或被 Memory 拒绝的提案改用 low 修复，并指出每条引文必须同时包含对象指称和属性，不能连续重复同样的无效快速提案。普通聊天请求没有这些覆盖，功能绑定和全局 Gemini 配置保持。首次关闭抽取思考用于避免思考耗尽预算而没有 JSON，抽取质量仍需真实模型验证，不能假设所有供应商都支持同一参数。

队列保留精确 scope 前序约束和未知 outbox 等待。每三个新任务后优先探查已到期重试，每个游标仍只取 64 条；一次选择最多分别探查重试和普通两页。被前序阻挡的任务不能越序，其他 scope 继续轮转。这给到期重试进展机会，不代表无限负载下有固定延时承诺；单个后台模型槽和角色提交窗口仍沿用原实现。

完成的事实由现有 memory-context 自动召回，普通问题无需“你记得吗”等触发词。纠正、遗忘及抑制旧来源重新出现继续由 Memory 现有修订与 proof 机制负责。本次没有另建第二套用户画像或长期存储。

内部运行能力端口增加 `extraction` 与 `retained_learning`（pending/completed/invalidated/blocked 的有无），不包含原文、人物标识或模型输出。completed 包括 committed/skipped，不能单凭任务完成就声称产生了事实；`memory_write_verification` 不自动升级为真实环境已验收。

跨产品联合用例：`tests/run_memory_learning_joint.ps1`，所有依赖路径均为必传，创建独立 `.runtime/memory-learning-joint` 数据、临时证书及回环端口；只有外部模型与渠道是合成替身，Platform、Companion、Memory、Gateway 均使用实际代码。当前用例使用协议 3 保存带对象身份的钢笔墨水事实、重启 Companion、关闭短期邻接，再验证普通问题的实际模型请求中包含长期记忆。Memory 使用独立发布合同目录时设置现有测试变量 `TIANSHU_CONTRACT_DIRECTORY`。它不证明真实模型提炼质量或 QQ 收发效果。

与 TS-117 成对集成，先 Memory 后 Companion，无新增数据库迁移。Platform 的功能模型选择服务本来已支持 memory，因此无需新增模型配置 API；现有 Platform 功能目录的 connected 静态文案尚未随本批修改，部署界面说明应由 Platform 集成时同步。

2026-10-14 对象区分：客户端接受抽取协议 2 和 3，拒绝未知版本；协议 3 提示模型在本次引文中标明具体对象，并在明确同一对象时复用 Memory 提供的 ID。稳定偏好等关于作者整体的事实使用 entity=null。模型不签发 ID、身份或权限；不同对象可共用属性名，不能按属性名将两个物品合并。旧的无 entity 事实不自动指定到新对象。日常聊天模型、功能模型选择和生产自动记忆开关均未由该协议改动改变。

TS-192：自动抽取先判断陈述本身是否具有持续价值，已知对象出现不等于这次动作是稳定事实。临时取物、清洗、充电或跑腿不因对象已在known_facts里就生成长期习惯；明确的通常存放位置、物品名称和反复习惯继续保留。混合消息只提取有持续价值的陈述，具体阶段计划保留所说时间和条件，不能变成永久偏好或已完成事件。规则仍在现有一次抽取提示中执行；没有增加模型调用、字段、第二套记忆库，也不宣称模型不会误判。Memory继续独立核验来源、精确引文、对象、有效时间与幂等提交。自然语言负例、稳定事实正例及混合句的真实提议和回执单独验收，不能仅看后台completed状态。
